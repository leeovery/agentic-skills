# Fonts via `@nuxt/fonts`

`@nuxt/fonts` self-hosts webfonts at build time. No FOIT, no third-party request at runtime, no FOUT if you set fallback metrics correctly. It's the right default for any Nuxt project that uses non-system fonts.

## Setup

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@nuxt/fonts'],

  fonts: {
    families: [
      { name: 'Geist',            provider: 'google', weights: [400, 500, 600, 700] },
      { name: 'Geist Mono',       provider: 'google', weights: [400, 500] },
      { name: 'Instrument Serif', provider: 'google', weights: [400], styles: ['normal', 'italic'] },
      { name: 'Space Grotesk',    provider: 'google', weights: [400, 500, 600, 700] }
    ]
  }
})
```

`provider: 'google'` resolves the font from Google Fonts. Other providers: `bunny`, `fontshare`, `local`, `fontsource`, `adobe`. NuxtFonts picks the first one that has the requested font.

The font is downloaded at build time, optimised, and served from your own origin. Production: zero third-party font requests.

## Wiring to Tailwind

Register the font family as a token in `main.css`:

```css
@theme static {
  --font-sans:    "Geist", "Helvetica Neue", Helvetica, Arial, sans-serif;
  --font-mono:    "Geist Mono", "JetBrains Mono", ui-monospace, Menlo, monospace;
  --font-serif:   "Instrument Serif", Georgia, serif;
  --font-grotesk: "Space Grotesk", "Helvetica Neue", Helvetica, Arial, sans-serif;
  --font-display: var(--font-sans);
}
```

Tailwind exposes these as `font-sans`, `font-mono`, `font-serif`, `font-grotesk`, `font-display`.

The font **name** in `--font-*` must match the name in `nuxt.config.ts > fonts.families`. NuxtFonts auto-discovers `@theme` declarations too, so if you list `--font-sans: "Geist"` in CSS, the `families` array can be omitted — but listing it explicitly is clearer and lets you set weights/styles.

## Weight subsetting

Only request the weights you actually use:

```typescript
fonts: {
  families: [
    { name: 'Geist', provider: 'google', weights: [400, 500, 700] }   // skip 600 if unused
  ]
}
```

Each weight is a separate file (~30–50 KB). A profligate `weights: [100, 200, 300, 400, 500, 600, 700, 800, 900]` adds 300+ KB to first-load. Audit which weights you actually render in templates (`font-medium`, `font-semibold`, `font-bold`) and request only those.

Italic styles double the file count: `styles: ['normal', 'italic']` means both — only request `italic` if you use it.

## Variable fonts

If the font has a variable axis, NuxtFonts uses the variable file when available — automatic. You still declare weights so the module knows what to validate against.

Variable fonts are usually the better default for displays: one file covers all weights, ~50 KB total instead of 200 KB across multiple weights.

## Preload strategy

NuxtFonts emits `<link rel="preload">` for fonts it detects in the critical render path. You can override:

```typescript
fonts: {
  families: [
    { name: 'Geist', provider: 'google', weights: [400, 500, 700], preload: true }
  ]
}
```

Preload selectively. Preloading every weight defeats the LCP win — the browser blocks rendering on the preload list. Preload only:

- The body font at the default weight (e.g. `Geist 400`)
- The display font at its primary weight if it's above-the-fold

Don't preload mono fonts unless code blocks are above the fold.

## Fallback metrics (avoid FOUT)

When a custom font loads, the page re-flows because the fallback (`Helvetica`, `Arial`) has different metrics. NuxtFonts mitigates this by injecting size-adjusted fallback `@font-face` declarations:

```css
/* auto-generated by @nuxt/fonts */
@font-face {
  font-family: 'Geist Fallback';
  src: local('Helvetica Neue'), local('Arial');
  size-adjust: 98.7%;
  ascent-override: 90%;
  descent-override: 22%;
  line-gap-override: 0%;
}
```

The fallback occupies the same vertical space, so re-flow is invisible. Mostly automatic.

If you see FOUT in production: confirm NuxtFonts is in `modules: []`, the font name in CSS matches `fonts.families`, and you're not double-loading via raw `<link>` tags in `app.head`.

## Local fonts

For fonts you've licensed and have as `.woff2` files:

```typescript
fonts: {
  families: [
    { name: 'Brand Sans', provider: 'local' }
  ]
}
```

Drop the files in `public/fonts/`. NuxtFonts auto-detects by name. For custom paths:

```typescript
fonts: {
  providers: {
    local: { paths: ['public/brand-fonts/'] }
  }
}
```

## Loading strategy: `font-display`

NuxtFonts defaults to `font-display: swap` — fallback renders immediately, real font swaps in when loaded. Right default for body text.

For above-the-fold display headings, consider `font-display: optional`:

```typescript
fonts: {
  families: [
    { name: 'Geist', provider: 'google', weights: [400, 700], display: 'optional' }
  ]
}
```

`optional` gives the browser ~100ms to load the font; if it doesn't make it, the fallback stays. No layout shift, no flash. Trade-off: some first-visit users see the fallback for that session.

Don't use `font-display: block` — invisible text until the font loads (FOIT), bad UX.

## Anti-patterns

- ❌ `<link href="https://fonts.googleapis.com/...">` in `app.head` while also using NuxtFonts — double loading
- ❌ Adding `@font-face` rules manually in CSS while NuxtFonts is configured — overrides NuxtFonts' optimised version
- ❌ Loading all 9 weights "just in case" — bundle bloat, slow LCP
- ❌ Loading italic when you don't use italic — same problem
- ❌ Hardcoding font URLs that point at third-party origins in production — defeats the self-hosting win
- ❌ Skipping fallback metrics for a font with very different proportions to the system fallback — visible reflow
